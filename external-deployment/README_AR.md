# دليل النسخة الاحتياطية والنقل الخارجي — مراسلة المؤسسة

> **الهدف:** يشرح هذا الدليل كيفية استعمال أرشيف المصدر المرفق كنسخة برمجية قابلة للنقل، وكيفية استكمال نسخ قاعدة البيانات والوسائط والأسرار قبل تشغيل المشروع على استضافة أخرى.

## 1. ما الذي يضمّه الأرشيف

| المكوّن | الحالة داخل أرشيف المصدر | ملاحظة النقل |
|---|---|---|
| الشيفرة الأمامية والخلفية | مضمن | React 19، Express 4، tRPC، Socket.IO وDrizzle. |
| مخطط قاعدة البيانات والترحيلات | مضمن | موجود تحت `drizzle/` و`drizzle/schema.ts`. |
| قفل التبعيات | مضمن | استخدم `pnpm install --frozen-lockfile`. |
| اختبارات المشروع | مضمنة | تحقق عبر `pnpm check && pnpm test`. |
| مفاتيح السر وملف `.env` الحقيقي | غير مضمن | لحماية المفاتيح؛ استعمل `.env.example` كبنية فقط. |
| بيانات العملاء والرسائل وطلبات الخدمة | غير مضمنة في أرشيف المصدر | يلزم تصدير قاعدة البيانات بصورة مستقلة ومشفرة. |
| الوسائط المرفوعة إلى التخزين | غير مضمنة في أرشيف المصدر | يلزم تصديرها من موفر التخزين أو استبدال روابطها بعد النقل. |

## 2. التشغيل المحلي من النسخة

استخدم Node.js 22 أو أحدث و`pnpm` 10. بعد فك الأرشيف، انسخ نموذج البيئة ثم أدخل بيانات بيئتك الخاصة:

```bash
cp external-deployment/.env.example .env
pnpm install --frozen-lockfile
pnpm check
pnpm test
pnpm run dev
```

لبناء نسخة الإنتاج وتشغيلها:

```bash
pnpm run build
NODE_ENV=production pnpm start
```

> لا ترفع ملف `.env` أو أرشيف الأسرار أو أي تصدير لقاعدة البيانات إلى مستودع عام.

## 3. نقل قاعدة البيانات والوسائط

يلزم إنشاء قاعدة MySQL/TiDB جديدة ثم تشغيل الترحيلات أو استيراد تصدير قاعدة البيانات المتوافق. يحتوي المشروع على جداول العملاء والمحادثات والرسائل والطلبات والمكالمات والحالات وتخصيص واجهة العميل. لا يكفي نقل الشيفرة وحدها لاسترجاع هذه البيانات.

المشروع الحالي يستخدم تخزيناً مرتبطاً بخدمة Forge/Manus لرفع الوسائط وتقديمها عبر مسارات `/manus-storage/*`. قبل النشر خارج المنصة، استبدل `server/storage.ts` و`server/_core/storageProxy.ts` بطبقة S3 أو R2 أو Blob Storage، ثم انقل الملفات المرفوعة إلى المزود الجديد مع الحفاظ على مفاتيحها أو تحديث الروابط في قاعدة البيانات.

## 4. الأجزاء التي تتطلب تهيئة أو استبدالاً خارج المنصة

| الجزء | الوضع الحالي | الإجراء الخارجي المطلوب |
|---|---|---|
| قاعدة البيانات | `DATABASE_URL` وDrizzle/MySQL | توفير MySQL/TiDB مُدار وتشغيل الترحيلات أو الاستيراد. |
| التخزين | Forge proxy و`/manus-storage/*` | توفير S3-compatible storage وتعديل طبقة التخزين. |
| تسجيل دخول المالك | Manus OAuth | استبدال OAuth أو تعطيله بصورة آمنة وفق سياسة الوصول الخاصة بك. |
| الذكاء الاصطناعي | مفاتيح Gemini/Forge | إدخال مفتاح ومزود خارجيين ثم مراجعة مسارات الاستدعاء. |
| الصوت | ElevenLabs | إدخال مفتاح ElevenLabs على الاستضافة الجديدة. |
| المهام المجدولة | Heartbeat/Manus | نقلها إلى cron أو job queue لدى مزود الاستضافة. |
| PWA وأيقونات التطبيق | تعتمد بعض المسارات على `/manus-storage` | استضافة الأيقونات في التخزين الخارجي وتحديث المسارات. |

## 5. التحقق قبل النشر وبعده

نفّذ الفحوص التالية بالترتيب: تحقق من التبعيات، ثم فحص الأنواع، ثم الاختبارات، ثم اتصال قاعدة البيانات، ثم رفع ملف اختبار إلى التخزين الجديد، ثم إنشاء محادثة واختبار الرسائل الفورية. لا تنقل نطاقك قبل تحقق هذه الخطوات على عنوان اختبار مستقل.

## 6. النسخة الكاملة للبيانات داخل Manus

أرشيف المصدر مفيد للتطوير والنقل، لكنه ليس بديلاً عن تصدير بيانات المهام: النسخة الرسمية للبيانات تشمل الشيفرة والوسائط وقاعدة البيانات والإعدادات والأسرار في لقطة زمنية واحدة. إذا كان حسابك ضمن نطاق النسخ الاحتياطي، استخدم أداة النسخ الرسمية وأنشئ تصديراً حديثاً، مع نسخة أخيرة بعد أي بيانات أو رسائل جديدة. لا تغيّر أسماء حزم النسخ الرسمية ولا تخلط أجزاء تصديرات مختلفة.[1][2]
