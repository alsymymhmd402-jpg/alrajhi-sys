# حوكمة وكيل التطبيق

## القاعدة الأساسية

وكيل التطبيق يحلل الطلب، ويحتفظ بسياق المحادثة، وينشئ **بطاقة معاينة** مفهومة قبل أي أثر على التطبيق. لا ينفذ أي إجراء عندما يرسل المالك رسالة أو عندما يقترح النموذج تغييراً؛ يبدأ التنفيذ فقط بعد ضغط المالك زر **«موافقة وتطبيق»** على بطاقة المعاينة ذاتها.

## حدود المعلومات

يُعطى الوكيل ملخصاً منضبطاً عن بنية Voice Circle، وصفحات لوحة التحكم، وإعدادات التجربة المسموح تعديلها. لا يحصل على مفاتيح API أو ملفات البيئة أو ملفات النظام أو قراءة مباشرة غير مقيدة لقاعدة البيانات. كما لا تعرض واجهة الدردشة بيانات العملاء الحساسة أو محتوى الأسرار ضمن السياق أو الردود.

## حدود التنفيذ

ينفذ الوكيل في هذه المرحلة الإجراءات الموجودة في قائمة آمنة فقط، مثل تحديث إعداد تجربة العميل المسموح بها أو اعتماد/إغلاق تنبيه تشغيلي. لا يحرر شيفرة المصدر، ولا ينفذ أوامر نظام، ولا يغير مخطط قاعدة البيانات، ولا يرسل رسائل أو يتصل بجهات خارجية من تلقاء نفسه. إذا طلب المالك تغييراً يحتاج تطويراً في الشيفرة، ينشئ الوكيل اقتراح تنفيذ واضحاً وسجل موافقة بدلاً من الادعاء بتنفيذه داخل الموقع.

## السجل والإشعارات

يحفظ النظام الرسائل، والاقتراحات، وقرارات الموافقة أو الإلغاء، ونتيجة التنفيذ. وتظهر أخطاء التشغيل المسجلة كتنبيهات قابلة للعرض داخل شاشة الوكيل؛ يمكن للوكيل اقتراح خطوة إصلاح، لكنها تخضع للموافقة نفسها ولا تخفي الخطأ أو تدّعي إصلاحه قبل تحقق النتيجة.
